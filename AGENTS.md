# AGENTS.md — World Crisis (Мировой Кризис)

Правила проекта для **всех** AI-агентов и для людей, которые пишут код в этом репозитории.
Файлы правил: `AGENTS.md` (этот файл). Нарушение этих правил = код не принимается.

---

## 1. Что это за проект

**World Crisis** — сатирическая настольно-ролевая стратегия про ядерную дипломатию, реализованная как
3D-сцена в Unity. Игрок играет за одну из 6 вымышленных держав, проходит 6 раундов: от заседаний
в бункере и Саммита ООН до ввода приказов и финального Расчёта (Reckoning).

| Параметр | Значение |
|---|---|
| Unity | `6000.6.6f1` (Unity 6.6) |
| Render pipeline | URP `17.6.0` (Asset/Settings, см. `Assets/Settings/`) |
| Ввод | Input System `1.20.0` (+ допускается fallback на legacy `UnityEngine.Input`) |
| UI | uGUI `2.6.0` + `TMPro` (TextMeshPro) |
| Сеть | собственная тонкая прослойка поверх `UnityWebRequest`/`System.Net.Sockets`, локальный тест + мультиплеер |
| Ассемблеи | скрипты лежат в `Assembly-CSharp` (без `.asmdef`, если не сказано иное) |
| Язык | C# 9 (LangVersion 9.0), .NET Standard 2.1 |

Язык игровых текстов и данных: **русский**. Комментарии в коде: **русский или английский**, единообразно в рамках файла.

## 2. ЖЁСТКОЕ ПРАВИЛО №1 — где живёт код

**Весь игровой код создаётся ТОЛЬКО в `Assets/_Game/Scripts/` и ТОЛЬКО в namespace `WorldCrisis`.**

```
Assets/_Game/Scripts/
├── Core/          ← ядро: сервисы, DI-lite, сеть, роутинг фаз, SceneVisualBinder, логгер
├── Data/          ← СЛОЙ ДАННЫХ: определения, конфиг, константы, генератор дефолтов
├── Voice/         ← озвучка/реплики/озвучка ИИ-персонажей (TextToSpeech, аудио-события)
├── Interaction/   ← взаимодействие с 3D-объектами сцены (raycast, drag, toggle, кнопки)
└── UI/            ← весь UI: экраны, виджеты, попапы, локализация текста
Assets/_Game/Shaders/         ← шейдеры ретро-пайплайна (Art Bible, раздел 6)
Assets/_Game/Resources/Config/   ← рантайм-конфиг (JSON), грузится через Resources.Load<TextAsset>
```

Требования к `using` в каждом файле:

```csharp
using System;
using System.Collections.Generic;
using UnityEngine;
using TMPro;                 // только если реально используется TextMeshProUGUI
using UnityEngine.InputSystem; // только в Core/ и Input/ коде, всегда через #if ENABLE_INPUT_SYSTEM

namespace WorldCrisis   // строго этот namespace, без под-namespaces вида WorldCrisis.Core.*
{
    // ...
}
```

Правила по namespace:
- Только `WorldCrisis`. Под-namespaces (`WorldCrisis.Core`) **запрещены** — иначе `using` в других слоях придётся дублировать.
- Имена классов: `PascalCase`. Приватные поля инстансов: `_camelCase`. `const`/статические readonly: `PascalCase` для констант-значений.
- Имена методов-событий: `OnXxx` только для Unity-колбэков (Unity так ищет). Остальные глаголы без `On`.

## 4. ЖЁСТКОЕ ПРАВИЛО №3 — зависимости и компиляция

**Запрещено:**
- Любые платные или сторонние ассеты из Asset Store (кроме уже установленных пакетов из `Packages/manifest.json`).
- Ручное добавление `.dll` в `Assets/Plugins/` без явного согласования с владельцем проекта.
- `#if false`-обёртки «на будущее» и мёртвый код.

**Разрешено (и должно использоваться):**
- `UnityEngine.*` (URP — `UnityEngine.Rendering.Universal`), стандартный API Unity.
- Ввод: `UnityEngine.InputSystem` **с fallback** на `UnityEngine.Input`, переключение — через `#if ENABLE_INPUT_SYSTEM` и/или собственный `InputService` в `Core/`.
- UI-текст: только `TMPro` (`TextMeshProUGUI`), либо `UnityEngine.UI.Text` как fallback.
- Сеть: собственная абстракция транспорта (`INetworkTransport` в `Core/`) с двумя реализациями: `LocalLoopbackTransport` (локальный тест, hot-seat/N имитация сети без процесса) и `TcpNetworkTransport`/`UnityWebRequest` (мультиплеер). Никаких NGO/Mirror/Photon без отдельного согласования.
- Сериализация данных: `JsonUtility` + `[Serializable]`, DTO-классы с публичными полями. Словари/enum-ключи в JSON не хранить — использовать `List<>`.

**Код обязан компилироваться с 0 ошибок и 0 новых warning'ов.** Перед тем как отчитаться о работе, агент обязан проверить компиляцию (см. §9).

## 5. Слой данных — источник истины

`Assets/_Game/Scripts/Data/GameDefinitions.cs` — единственный источник правды по балансу.

- **Никаких магических чисел в игровом коде.** Деньги, стоимости, проценты экологии, число раундов, лимиты — только через:
  - `EconomyConstants` (const-ы, если значение не меняемо никогда),
  - `GameConfig.Costs` / `GameConfig.Ecology` (если значение должно редактироваться в JSON-конфиге).
- Никаких `switch` по странам/доктринам вне `CountryDefinition` / `SecretDoctrine`: добавил новую державу → меняешь только данные и фабрику `CreateDefault(...)`.
- Все DTO — `[Serializable]`, поля `public`, без свойств (JsonUtility не умеет свойства).
- `float`, не `double` (JsonUtility не поддерживает `double`).
- Дефолтный конфиг генерируется кодом (`GameDefinitions.CreateDefaultConfig()`), поэтому игра обязана работать сразу, без ручного заполнения инспектора. JSON в `Assets/_Game/Resources/Config/` генерируется из кода и может быть перезаписан заново.

**Как это работает на практике:**
- `Assets/_Game/Resources/Config/default_game_config.json` создаётся **автоматически** движком при загрузке домена редактора (`GameConfigEditorMenu.AutoEnsureConfigAsset`), и только если файла ещё нет. Вручную его создавать и коммитить изменения баланса в нём не нужно — правки дизайна делаются в `EconomyConstants`/`GameConfig`, файл перегенерируется через меню.
- В редакторе есть меню `World Crisis`:
  - `Сгенерировать дефолтный конфиг` — перезаписать JSON из кода;
  - `Проверить и восстановить конфиг` — дописать недостающие державы/доктрины в старый JSON;
  - `Печать баланса в консоль` — вывести все стоимости, держав и доктрин (быстрая сверка с этим файлом).
- В рантайме `GameDefinitions.GetConfig()` сам читает `Resources.Load<TextAsset>("Config/default_game_config")`, а при отсутствии/битом JSON — отдаёт рабочий дефолт в памяти и пишет одно предупреждение в лог. Игра не падает никогда.
- Редакторный код слоя данных лежит в `Assets/_Game/Scripts/Data/Editor/` (→ `Assembly-CSharp-Editor`) и целиком обёрнут в `#if UNITY_EDITOR`.

## 6. Слои и зависимости (направление зависимостей)

```
Data  ──────────►  (ни от кого, кроме UnityEngine)
Core  ──────────►  Data
Voice ──────────►  Data, Core
Interaction ────►  Data, Core   (сюда же доступ к SceneVisualBinder)
UI    ──────────►  Data, Core
```

- `Data` **не знает** про `Core`, `UI` и любые MonoBehaviour.
- `UI` не содержит геймплейной логики — только отображение и вызов методов сервисов.
- `Interaction` не знает про `UI`.
- Логика симуляции (деньги, раунды, пакты, ракеты, экология) — **в `Core`**, а не в UI и не в MonoBehaviour-компонентах сцены.
- Состояние мира хранится в одном месте (`GameStateService` в `Core`), компоненты сцены — без собственного состояния.

## 7. Правила написания кода

1. **Никаких `UnityEditor` в рантайм-коде.** Только внутри `#if UNITY_EDITOR`; редакторный код — в папке `Editor/` рядом со скриптом, но **вне** `Assets/_Game/Scripts/` запрещено класть `.cs` в `GeneratedProps/`.
2. **Никаких исключений в игровом цикле.** Ошибки — `Debug.LogWarning`/`LogError` с префиксом `[WorldCrisis]` + безопасный fallback. Исключения только в `assert`-сценариях разработки.
3. **Не вызывать `FindObjectOfType`/`GameObject.Find` в `Update`.** Поиск — один раз в `Awake`/`Start`, результат кэшируется. `Update` — только логика и лёгкие проверки; тяжёлое — в корутинах/таймерах.
4. **События — через C# `event Action<...>`**, подписка/отписка в паре (`OnEnable`/`OnDisable`), без статических утечек. Обработчики — без `async void` (только `void` + корутины, либо `UniTask`-запрещён).
5. `Time.deltaTime`, а не `Time.time` для геймплейных таймеров; пауза учитывается фазой (`GamePhase`).
6. Фазы: единственный источник истины по фазе — `Core/PhaseController`. UI и `Interaction` только читают текущую фазу через сервис и подписываются на её смену.
7. Стиль: 4 пробела, скобки с новой строки (Allman), `using` внутри `namespace` **не** ставим — только сверху, сортировка: `System*`, затем `UnityEngine*`, затем `TMPro`, затем пустая строка.
8. Комментарии — по делу: «зачем», а не «что». Логика, завязанная на числа из баланса, ссылается на `EconomyConstants` в комментарии.
9. Никаких `public` полей для рантайм-состояния в MonoBehaviour — `[SerializeField] private` + публичные геттеры.
10. Новый файл `.cs` обязан содержать шапку слоя:
```csharp
// World Crisis | Слой: Data | Ответственный: <имя агента>
// <одна строка: зачем файл>
```

## 8. Работа с 3D-объектами и UI

- Любой доступ к визуалу сцены — через `SceneVisualBinder` (`Core`). Биндер сам ищет объекты (включая `GetComponentsInChildren(true)`), сам кэширует, сам переживает отсутствие.
- Интерактив (перетаскивание, нажатие, тумблер, шредер, крышка) — `Interaction/`: наследники `MonoBehaviour` с `Collider`/`IPointerClickHandler`, без доступа к данным напрямую — только к `Core`-сервисам.
- UI-тексты — только `TMPro`. Длинные строки выносятся в data-слой/локализацию, в коде не хардкодить длинные фразы (>80 символов) — только ключи или короткие подписи.
- Анимации/эффекты — URP-совместимые. Шейдеры проекта лежат в `Assets/_Game/Shaders/` и принадлежат графическому пайплайну (Art Bible, раздел 6): агент их пишет и правит, но **только** там. Папка `Assets/Shaders/` остаётся зарезервированной и ссылочной (см. §3).
